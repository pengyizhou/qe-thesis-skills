贯穿全程的六条规矩Six rules that hold throughout

  1. 何时算 final，由你说You say when it is finalClaude 不自己加审批关；导师的批准和评论，按你的转述带日期记进 stage status。Claude adds no approval gate of its own; your supervisor’s approval and comments go into the stage status with the date, as you report them.
  2. 两遍不混，写问题时不找文献Passes stay apart; no references while writing questionsPass A 没批准，不给你看任何 Pass B 内容；关于文献的前提先标 [TBD: premise to be checked at the reference step]，到第 3 步再查。Nothing from Pass B is shown before Pass A is approved; a premise about the literature is tagged [TBD: premise to be checked at the reference step] and checked in step 3.
  3. 改动只波及下游Changes only reach downstream随时可以跳回任何一章；改了早先的 stage，就重跑它下游的一致性检查；Pass B 之后改一个主问题，只作废它自己的子问题。You can jump back to any chapter at any time; a change to an earlier stage re-runs the consistency checks downstream of it; a main question changed after Pass B invalidates only its own sub-questions.
  4. 后加的内容，小规模重走第 3 步Later additions rerun step 3 in small新的子问题或文献：一个 discovery 子代理、元数据核对、两级精读、引文比对；你要求只读一遍时照做，记成 single read 进待核清单。A new sub-question or reference gets one discovery sub-agent, the metadata check, the two-tier reading and the quote check; if you ask for a single read, it is done and listed as a single read in the open checks.
  5. 不凭记忆Nothing from memory书目字段、引文和数字都从记录、原文或核过的 notes 来；找不到就写 not found 或 [TBD: source needed]。Bibliographic fields, quotes and numbers come from the record, the text or the checked notes; where none has it, the answer is not found or [TBD: source needed].
  6. 页面上的改动只算提议Changes on the page are proposals问题清单和 CSV 是你的：证据页上的移动、改写、排序记在 build 自己的 maps 里，你要求时才写回问题清单。The question list and the CSV are yours: moves, rewordings and reordering on the evidence page are recorded in the build’s own maps and written back to the question list only when you ask.
